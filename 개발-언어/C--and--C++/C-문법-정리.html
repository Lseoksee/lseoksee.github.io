    문자열 저장/출력 처리

    여기서 %s가 일반적으로 문자열 출력을 위한 거라고 하는데, 주의해야 될것이 \0문자열 즉, 바이너리 값으로 0이 존재할 경우 해당 부분 까지만 출력이 된다.

    다른 언어들에서처럼 디버깅 목적으로 printf를 사용하려고 할 때 문제는 바이너리 데이터를 문자열로 출력하려고 시도할 경우, \0(0x00)값을 마주한다면 문자열이 끝났다고 판단하여 멈춰버린다.

    만일 \0을 포함하여 모든것을 출력하길 원한다면 fwrite 를 사용하자

    당연하지만 실제 C언어에서 문자열을 다룰경우 \0값은 취급하지 않는다.

    참고로 문자열 선언 시 아래 처럼 선언한 경우 맨 뒤에 \0을 자동 삽입해주는데

    아래처럼 선언한 경우에는 삽입되지 않으므로 수동으로 \0을 삽입해야 한다. 안 그러면 실행 시 올바른 문자열 범위를 파악하지 못해 이상한 값이 저장된다.

    주의

    • 메모리 동적 할당은 실행 시 필요한 만큼 유동적으로 늘렸다 줄였다 하겠다는게 아님!

    • 구조체 등에서 초기화를 할 시 해당 구조체의 필요한 크기만큼 공간을 할당하겠다는 거라서 예를들어 이것을 동적리스트 처럼 사용한다거나 하는것은 안됨

    • 어떤 구조체를 여러개 저장해야되는 경우 아래처럼 사용하거나 realloc() 함수를 사용

    스택(Stack) 변수, 힙(Heap) 변수

    Stack

    메모리에 Stack 영역에 저장되는 변수 실제 물리적 램과 가장 가깝기 때문에 가장 빠른 속도를 지님 함수 호출 시 자동으로 할당되고, 해제됨

    실제 메모리에서 CPU와 가깝게 작동하기 위해서 만들어진 부분이라 용량이 좀 작음

    • 지역에 선언된 경우 주소를 리턴 할 경우 함수가 종료되면 할당을 해제 하기 때문에 오류가 난다
    • 위에 예시처럼 배열에도 똑같이 적용되므로 혹여나 배열도 포인터 처럼 쓰면 되 라는 인식으로 함수 반환을 배열로 주면 안된다.
    • 즉 C언어에서는 지역변수 배열 반환이 안된다.
    • 배열에 경우 따로 Heap변수로 wapping 해야되고(문자열에 경우 strcpy()) 일반 변수는 최대한 값으로 반환하도록 해야 한다 (아니면 위에처럼 memcpy() 등으로 Heap변수로 wapping이 필요)

    Heap

    메모리에 Heap 영역에 저장되는 변수 Stack영역 보다는 상대적으로 느리게 작동 프로그래머가 직접 메모리를 할당하고, 해제 해야 함

    사실상 일반적으로 램이 사용하는 영역을 가르킴

    • Heap 변수만 할당 뒤 free()로 해제 해야 함
